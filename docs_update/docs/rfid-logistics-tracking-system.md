# 아진산업 RFID 기반 물류 추적 시스템 명세서

## 문서 정보
- **버전**: 1.0.0
- **작성일**: 2025-11-17
- **기반 헌법**: Constitution v1.0.0
- **목적**: RFID 기반 팔레트 추적 시스템의 전체 흐름 및 핵심 요구사항 정의

---

## 1. 시스템 개요

### 1.1 비즈니스 목적
차체 부품 제조 공정에서 원자재부터 완제품까지 전 과정을 RFID 팔레트로 추적하여:
- 제품 불량 발생 시 원자재까지 역추적 가능
- 원자재 불량 발견 시 해당 원자재로 만든 모든 제품 추적 가능
- 실시간 공정 현황 모니터링
- FIFO(선입선출) 위반 방지

### 1.2 시스템 구성
```
┌─────────────────┐
│ RFID 리더기 (N개)│  각 공정의 IN/OUT/HOLD/DEFECT/FINISH 위치에 고정 설치
│  포트 고유 식별  │  포트 정보로 공정/위치 자동 판별
└────────┬────────┘
         │ 스캔 이벤트 전송 (EPC + 포트)
         ↓
┌─────────────────┐
│  임베디드 시스템  │  리더기 ↔ API 서버 중계
│  - 스캔 중계    │  - 네트워크 장애 시 로컬 큐잉
│  - 피드백 제어   │  - 부저/LED 제어
└────────┬────────┘
         │ HTTP API 호출
         ↓
┌─────────────────┐
│   API 서버       │  비즈니스 로직 처리
│  - 포트 → 공정   │  - 포트로 공정/위치 식별
│  - 상태 전이    │  - 팔레트 상태 관리
│  - 검증 로직    │  - FIFO, 오투입, 완제품 검증
│  - 추적성 제공   │  - 정방향/역방향 추적 쿼리
└────────┬────────┘
         │
    ┌────┴────┐
    ↓         ↓
┌───────┐ ┌───────┐
│  DB   │ │  웹   │  관리 및 모니터링
│       │ │       │  - 포트-공정 매핑 설정
│       │ │       │  - 마스터 데이터 관리
│       │ │       │  - 실시간 모니터링
│       │ │       │  - 드릴다운 추적 조회
└───────┘ └───────┘
```

### 1.3 핵심 프로세스 흐름

**중요**: 리더기는 고정된 위치, 팔레트는 각자 역할(소비용/생산용)을 가짐

#### 전체 흐름
```
[원자재 입고]
코일 번호 등록 (예: C059461B)
LOT 생성 (원자재 연결)
     ↓
[샤링 OUT 리더기] - 첫 공정 (특수 케이스)
1) 빈 팔레트 + RFID 부착
2) 샤링 OUT 리더기 첫 태깅: Generated → Empty
3) 공정 외부에서 제품 적재
4) 샤링 OUT 리더기 재태깅: Empty → Stock
     ↓
[프레스 IN 리더기] - 소비용 팔레트
1) Stock 팔레트 프레스 IN 첫 태깅: Stock → Consuming
   (FIFO 검증, 품번 검증)
2) 공정에서 제품 소비
3) 빈 팔레트를 프레스 IN 재태깅: Consuming → Deregistered
     ↓
[프레스 OUT 리더기] - 생산용 팔레트
1) 새 빈 팔레트 프레스 OUT 첫 태깅: Empty → Producing
2) 공정에서 제품 적재
3) 만차 팔레트를 프레스 OUT 재태깅: Producing → Stock
     ↓
[조립 IN 리더기] - 소비용 팔레트
1) Stock 팔레트 조립 IN 첫 태깅: Stock → Consuming
2) 공정에서 제품 소비
3) 빈 팔레트를 조립 IN 재태깅: Consuming → Deregistered
     ↓
[조립 OUT 리더기] - 생산용 팔레트 (완제품)
1) 새 빈 팔레트 조립 OUT 첫 태깅: Empty → Producing
2) 공정에서 완제품 조립 및 적재
3) 만차 팔레트를 조립 OUT 재태깅: Producing → Finished
   (구성 요소 자동 기록)
     ↓
[RETURN 리더기] - 출하 후 빈 팔레트 회수
빈 팔레트 태깅: Finished → Deregistered
```

**핵심 개념**:
- **IN 리더기**: 소비용 팔레트 전용 (첫 태깅: 투입, 재태깅: 소비 완료)
- **OUT 리더기**: 생산용 팔레트 전용 (첫 태깅: 적재 시작, 재태깅: 적재 완료)
- **샤링만 예외**: OUT 리더기를 2회 태깅 (Empty → Stock, Producing 생략)

#### 검증 흐름
```
RFID 스캔
    ↓
포트로 공정/위치 식별
    ↓
팔레트 조회 (EPC → 팔레트 → LOT → 품번)
    ↓
검증 1: 오투입 (품번 불일치)
  → 차단 (부저 3회, 빨간 LED)
  → 투입 불가 (상태 변경 없음)
    ↓
검증 2: FIFO (더 오래된 재고 존재)
  → 경고 (부저 3회, 노란 LED)
  → 무시하고 투입 가능
  → 이력에 "FIFO 위반" 기록
    ↓
검증 3: 완제품 (Finished 전환 시)
  → parts.is_final_product = TRUE 확인
  → 중간품이면 차단
    ↓
상태 전이 + 이력 기록
    ↓
피드백 (부저 1회, 녹색 LED)
```

## 2. 시스템 컴포넌트별 역할

### 2.1 임베디드 시스템

**핵심 역할**:
1. **RFID 리더기 연결**: 고정형 리더기와 시리얼/네트워크 통신
2. **스캔 이벤트 중계**: EPC + 포트 정보 → API 서버 전송
3. **피드백 제어**: API 응답에 따라 부저/LED 제어
4. **장애 복구**: 네트워크 끊김 시 로컬 큐에 저장 → 복구 후 재전송

**중요 흐름**:
```
리더기에서 태그 스캔
    ↓
EPC 파싱 + 중복 제거 (500ms 윈도우)
    ↓
포트 정보 확인 (예: COM3, 192.168.1.100:9001)
    ↓
API 서버로 전송
{
  "epc": "E280...",
  "port_name": "COM3",
  "scan_time": "2025-11-17T09:23:45.123Z"
}
    ↓
API 응답 수신
{
  "success": true,
  "feedback": {
    "pattern": "SUCCESS",  // or WARNING, ERROR
    "count": 1,
    "led_color": "GREEN"
  }
}
    ↓
부저/LED 실행
```

**장애 처리**:
- API 서버 연결 실패 → 로컬 큐 저장 (최대 1000개)
- 연결 복구 → 큐에서 순차 전송 (원래 타임스탬프 유지)

### 2.2 API 서버

**핵심 역할**:
1. **포트 기반 공정 식별**: port_name → 공정 + 위치 타입 자동 매핑
2. **상태 전이 관리**: 9가지 팔레트 상태를 헌법 규칙에 따라 관리
3. **검증 로직 실행**: FIFO, 오투입, 완제품 검증
4. **양방향 추적**: 코일 → 제품 / 제품 → 코일
5. **데이터 제공**: 웹 애플리케이션에 필요한 데이터 제공

**핵심 API 흐름**:

#### 2.2.1 RFID 스캔 처리 (POST /api/v1/rfid/scan)
```
요청 수신
  ├─ epc: "E280..."
  ├─ port_name: "COM3"
  └─ scan_time: "..."
    ↓
1. 포트로 공정/위치 조회
   SELECT process_id, location_type 
   FROM rfid_reader_locations 
   WHERE port_name = 'COM3'
    ↓
2. EPC로 팔레트 조회
   SELECT * FROM pallets WHERE rfid_epc = 'E280...'
    ↓
3. 상태 전이 결정
   현재 상태 + 공정 + 위치 타입 → 다음 상태
   
   예) 샤링 OUT + Empty → Stock
   예) 프레스 IN + Stock → Consuming
   예) 조립 OUT + Producing (완제품) → Finished
    ↓
4. 검증 로직 실행
   ├─ 오투입 검증
   │  └─ 팔레트 LOT 품번 vs 공정 요구 품번
   │     불일치 → 차단 (에러 반환)
   │
   ├─ FIFO 검증 (Stock → Consuming 전환 시)
   │  └─ 같은 품번의 더 오래된 재고 존재?
   │     존재 → 경고 (진행 가능)
   │
   └─ 완제품 검증 (Producing → Finished 전환 시)
      └─ parts.is_final_product = TRUE?
         FALSE → 차단 (에러 반환)
    ↓
5. 트랜잭션 처리
   BEGIN
     UPDATE pallets SET status = '새상태', ...
     INSERT INTO pallet_histories (...)
     IF 조립 완료 THEN
       INSERT INTO assembly_components (...)
     END IF
   COMMIT
    ↓
6. 피드백 생성
   성공 → {pattern: "SUCCESS", count: 1, led: "GREEN"}
   FIFO 위반 → {pattern: "WARNING", count: 3, led: "YELLOW"}
   오류 → {pattern: "ERROR", count: 3, led: "RED"}
    ↓
응답 반환
```

#### 2.2.2 상태 전이 규칙

**중요**: 리더기는 고정 위치, 팔레트는 같은 리더기를 2회 태깅

**샤링 OUT 리더기 (첫 공정 예외)**:
- 첫 태깅: `Empty → Empty` (RFID 매칭 확인만)
- 재태깅: `Empty → Stock` (적재 완료)
- 이유: 적재가 공정 외부에서 발생 (Producing 생략)

**중간품 공정 IN 리더기 (소비용)**:
- 첫 태깅: `Stock → Consuming` (투입, FIFO 검증)
- 재태깅: `Consuming → Deregistered` (소비 완료, 빈 팔레트)

**중간품 공정 OUT 리더기 (생산용)**:
- 첫 태깅: `Empty → Producing` (적재 시작)
- 재태깅: `Producing → Stock` (적재 완료, 만차)

**완제품 조립 IN 리더기 (소비용)**:
- 첫 태깅: `Stock → Consuming` (투입)
- 재태깅: `Consuming → Deregistered` (소비 완료)

**완제품 조립 OUT 리더기 (생산용)**:
- 첫 태깅: `Empty → Producing` (조립 시작)
- 재태깅: `Producing → Finished` (조립 완료, 완제품 전용)
- 추가: 조립품 구성 요소 자동 기록

**RETURN 리더기 (빈 팔레트 회수)**:
- 태깅: `Finished → Deregistered` (출하 후 회수)

#### 2.2.3 추적성 조회

**정방향 추적** (GET /api/v1/trace/forward?coil_number=C059461B):
```
원자재 (코일 번호)
  └─ 생산된 중간품 LOT
      ├─ 팔레트 목록
      └─ 사용된 조립품
          └─ 최종 완제품
```

**역방향 추적** (GET /api/v1/trace/backward?lot_no=ASM-XXX):
```
완제품 (조립품 LOT)
  └─ 구성 요소
      ├─ 중간품 LOT
      │   └─ 원자재 (코일)
      └─ 하위 조립품
          └─ 재귀적으로 하위 구성 요소
```

**드릴다운 검색** (GET /api/v1/trace/drill-down?search=...):
- 검색어 유형 자동 감지 (품번, LOT, 코일, 팔레트)
- 정방향 + 역방향 결합 결과 반환
- 계층 구조로 관련 항목 제공

### 2.3 웹 애플리케이션

**핵심 역할**:
1. **공정 배치 설정**: 포트 → 공정 + 위치 타입 매핑
2. **공정 순서 정의**: 드래그 앤 드롭으로 순서 설정 → 추적 범위 결정
3. **마스터 데이터 관리**: 원자재, 품번, LOT, 팔레트 등록
4. **실시간 모니터링**: 공정별 팔레트 현황, 스캔 이벤트 로그
5. **드릴다운 추적**: 통합 검색 → 관련 항목 계층적 표시

**핵심 화면 흐름**:

#### 2.3.1 공정 배치 관리
```
목적: 포트별로 공정을 자유롭게 배치

[리더기 등록]
입력 필드:
  - 포트 이름 (COM3, 192.168.1.100:9001)
  - 공정 선택 (샤링, 프레스, 조립, 출하)
  - 위치 타입 (IN, OUT, HOLD, DEFECT, FINISH)
  - 설명 (프레스 1500T 투입구)
    ↓
저장 → rfid_reader_locations 테이블
    ↓
실시간 연결 상태 표시
  - 녹색: 정상 연결
  - 빨간색: 연결 끊김

[공정 순서 정의]
드래그 앤 드롭으로 순서 변경
  샤링 → 프레스 → 조립 → 출하
    ↓
process_order 업데이트
    ↓
팔레트 추적 범위 결정
  (어떤 공정을 거쳐야 하는지)
```

#### 2.3.2 마스터 데이터 등록
```
[원자재 등록]
코일 번호, 공급업체, 입고일자, QC 상태
  → raw_materials 테이블

[품번 등록]
품번, 품명, 차종, 조립품 여부, 완제품 여부
  → parts 테이블

[LOT 등록]
중간품 LOT:
  - LOT 번호, 품번, 공정, 원자재(필수), 수량, 생산일자
  → lots 테이블
  
조립품 LOT:
  - LOT 번호, 품번, 조립일자, 수량
  → assembly_lots 테이블
  
구성 요소 추가:
  - 조립품 LOT + 중간품 LOT/하위 조립품
  → assembly_components 테이블
  → 트리거로 assembly_level 자동 계산

[팔레트 등록]
팔레트 번호 + RFID EPC
  → pallets 테이블 (Generated 상태)
  
LOT 연결:
  팔레트 선택 → LOT 검색 → 연결
  → pallets.lot_id or assembly_lot_id 업데이트
```

#### 2.3.3 실시간 모니터링
```
목적: 현재 공정 상태 실시간 확인

[공정별 탭]
샤링 | 프레스 | 조립 | 출하

[선택된 공정 현황]
활성 팔레트 수: 8개
상태별 분포:
  - Producing: 2개
  - Consuming: 3개
  - Stock: 3개

팔레트 목록 (실시간 업데이트):
┌─────────────────────────────────┐
│ 팔레트  │ LOT    │ 품번  │ 상태 │
├─────────────────────────────────┤
│ PLT-001│LOT-001 │71412 │ 🟢 C │
│ PLT-002│LOT-002 │71412 │ 🟡 P │
│ PLT-003│LOT-001 │71412 │ 🔵 S │
└─────────────────────────────────┘

최근 이벤트 (실시간):
  09:25:30 PLT-001 Stock → Consuming
  09:24:15 ⚠️  FIFO 위반 경고 (PLT-003)

WebSocket 또는 SSE로 1초마다 업데이트
```

#### 2.3.4 드릴다운 추적 조회
```
목적: 어떤 검색어로도 관련 부품 추적

[통합 검색]
입력: 품번, 품명, LOT, 코일, 팔레트 번호
  → 자동 완성 지원

[검색 결과 - 계층 구조]
📦 품번: 71412-T6000S
   품명: PNL-FR DR INR, LH
   
   ┌─ 📤 원자재 (정방향)
   │  └─ 🔗 C059461B (클릭 가능)
   │
   ┌─ 📋 생산 LOT (3건)
   │  ├─ 🔗 LOT-20251017-001 [접기/펼치기]
   │  │  ├─ 팔레트: PLT-2025-001 (Stock)
   │  │  └─ 사용처: ASM-20251018-001
   │  │
   │  ├─ 🔗 LOT-20251016-005
   │  └─ 🔗 LOT-20251015-003 ⚠️ 오래됨
   │
   └─ 📥 사용된 조립품 (역방향)
      ├─ 🔗 ASM-20251018-001
      │  └─ 최종 제품: ASSY-DOOR
      └─ 🔗 ASM-20251018-002

클릭 시 해당 항목으로 이동 (드릴다운)
```

#### 2.3.5 재고 현황
```
목적: FIFO 관리

[재고 목록 - 생산일자순 정렬]
┌────────────────────────────────┐
│품번   │공정 │생산일│수량│경과일│
├────────────────────────────────┤
│71412 │프레스│10-15│400│🔴 5 │
│      │     │10-16│400│🟡 4 │
│      │     │10-17│400│🟢 2 │
└────────────────────────────────┘

색상 구분:
  🔴 5일 이상: 긴급 조치 필요
  🟡 3-4일: 주의
  🟢 0-2일: 정상
```

### 2.4 데이터베이스

**핵심 테이블 (10개)**:
- **마스터 (4개)**: raw_materials, parts, processes, rfid_reader_locations
- **생산 (3개)**: lots, assembly_lots, assembly_components
- **RFID (3개)**: pallets, pallet_histories, rfid_tags

**추적성 뷰 (6개)**:
- v_pallet_status: 팔레트 현황
- v_stock_inventory: 재고 현황 (FIFO용)
- v_pallet_trace: 공정 이력
- v_assembly_trace: 조립 추적
- v_material_forward_trace: 정방향 (코일 → 제품)
- v_product_backward_trace: 역방향 (제품 → 코일)

**무결성 규칙**:
- 팔레트는 중간품 LOT 또는 조립품 LOT 중 하나와만 연결
- 모든 중간품 LOT는 원자재 연결 필수
- 추적 키(코일, LOT, 팔레트, EPC) 절대 삭제/재사용 금지
- pallet_histories 절대 삭제 금지 (불변 로그)

## 3. 핵심 시나리오

### 3.1 정상 흐름: 샤링 → 프레스 → 조립

```
[Step 1: 샤링 OUT 리더기 - 첫 공정]
1-1) 빈 팔레트에 RFID 부착
1-2) 샤링 OUT 리더기 첫 태깅
   임베디드 → API: {epc: "E280...", port_name: "COM3"}
   API: Empty → Empty (매칭 확인)
   부저 1회
   ↓
1-3) 샤링 공정 외부에서 제품 적재
   ↓
1-4) 샤링 OUT 리더기 재태깅 (같은 리더기)
   임베디드 → API: {epc: "E280...", port_name: "COM3"}
   API: Empty → Stock (적재 완료)
   부저 1회 + 녹색 LED
   웹: 재고 현황 업데이트

[Step 2: 프레스 IN 리더기 - 소비 시작]
2-1) Stock 팔레트를 프레스 IN 리더기 첫 태깅
   임베디드 → API: {epc: "...", port_name: "192.168.1.100:9001"}
   API: FIFO 검증 (경고만, 진행 가능)
   API: 오투입 검증 (차단)
   API: Stock → Consuming
   부저 1회
   웹: 모니터링 업데이트
   ↓
2-2) 프레스 공정에서 제품 소비
   ↓
2-3) 빈 팔레트를 프레스 IN 리더기 재태깅 (같은 리더기)
   임베디드 → API: {epc: "...", port_name: "192.168.1.100:9001"}
   API: Consuming → Deregistered
   부저 1회
   RFID 태그 회수 가능

[Step 3: 프레스 OUT 리더기 - 생산]
3-1) 새 빈 팔레트를 프레스 OUT 리더기 첫 태깅
   임베디드 → API: {epc: "...", port_name: "192.168.1.100:9002"}
   API: Empty → Producing
   부저 1회
   ↓
3-2) 프레스 공정에서 제품 적재
   ↓
3-3) 만차 팔레트를 프레스 OUT 리더기 재태깅 (같은 리더기)
   임베디드 → API: {epc: "...", port_name: "192.168.1.100:9002"}
   API: Producing → Stock
   부저 1회 + 녹색 LED
   웹: 재고 추가

[Step 4: 조립 IN 리더기 - 소비]
4-1) Stock 팔레트 (프레스 중간품) 조립 IN 리더기 첫 태깅
   API: Stock → Consuming
   ↓
4-2) 소비 완료 후 빈 팔레트 조립 IN 리더기 재태깅
   API: Consuming → Deregistered

[Step 5: 조립 OUT 리더기 - 완제품]
5-1) 새 빈 팔레트 조립 OUT 리더기 첫 태깅
   API: Empty → Producing
   ↓
5-2) 조립 완료
   ↓
5-3) 만차 팔레트 조립 OUT 리더기 재태깅
   API: 완제품 검증 (is_final_product = TRUE)
   API: Producing → Finished
   API: assembly_components 자동 기록
   트리거: assembly_level 자동 계산
   웹: 완제품 등록

[Step 6: RETURN 리더기 - 출하 후]
빈 팔레트 RETURN 리더기 태깅
   API: Finished → Deregistered
   RFID 태그 회수 가능
```

### 3.2 예외 흐름

#### FIFO 위반 경고
```
Stock 팔레트 투입 시도
   ↓
API: FIFO 검증
   - 같은 품번에서 더 오래된 재고 존재
   ↓
API: 경고 메시지 생성
{
  "warning": {
    "type": "FIFO_VIOLATION",
    "oldest_stock": {
      "lot_no": "LOT-20251015-003",
      "production_date": "2025-10-15",
      "days_old": 2
    }
  }
}
   ↓
임베디드: 부저 3회 + 노란 LED
   ↓
웹: 경고 팝업 표시
   ↓
작업자 판단
  - 무시하고 투입 (긴급 생산, 특별 지시)
  - 오래된 재고로 교체
   ↓
IF 무시하고 투입:
  API: Stock → Consuming (정상 진행)
  API: 이력에 "FIFO 위반 무시" 기록
```

#### 오투입 차단
```
잘못된 품번 팔레트 투입 시도
   ↓
API: 오투입 검증
   - 요구 품번: 71412-T6000S
   - 실제 품번: 76211-GI000
   - 불일치!
   ↓
API: 에러 반환
{
  "success": false,
  "error": {
    "type": "WRONG_PART",
    "message": "품번 불일치 - 투입 불가",
    "expected": "71412-T6000S",
    "actual": "76211-GI000"
  }
}
   ↓
임베디드: 부저 3회 + 빨간 LED
   ↓
웹: 에러 알림
   ↓
상태 변경 없음 (투입 차단)
   ↓
작업자가 올바른 팔레트로 교체
```

#### 네트워크 장애
```
API 서버 연결 끊김
   ↓
임베디드: 로컬 큐에 스캔 이벤트 저장
{
  "epc": "E280...",
  "port_name": "COM3",
  "scan_time": "2025-11-17T09:25:30.123Z"
}
   ↓
큐 크기: 최대 1000개
   ↓
5초마다 재연결 시도
   ↓
연결 복구
   ↓
큐에서 순차 전송 (100ms 간격)
   ↓
API: 원래 타임스탬프로 이력 기록
```

## 4. 비기능 요구사항

### 4.1 성능
- **RFID 스캔 → 피드백**: 500ms 이내
- **API 응답**: 1초 이내
- **추적성 조회**: 3초 이내
- **동시 접속**: 50명 이상
- **초당 RFID 스캔**: 10개 처리 가능

### 4.2 가용성
- **시스템 가동률**: 99% 이상
- **장애 복구**: 1시간 이내
- **네트워크 장애 대응**: 로컬 큐잉으로 데이터 손실 방지

### 4.3 확장성
- **공정 추가**: 설정만으로 가능 (코드 변경 불필요)
- **리더기 추가**: 플러그 앤 플레이 (포트 등록만)
- **팔레트 수**: 10,000개 이상 지원

### 4.4 보안
- **인증**: 토큰 기반
- **권한**: 역할 기반 (작업자/관리자)
- **감사 로그**: 모든 중요 작업 기록
- **데이터 암호화**: 전송 구간

### 4.5 운영
- **로그 보관**: 최소 6개월
- **백업**: 일일 자동
- **모니터링**: 시스템/리더기 상태
- **알림**: 장애 발생 시 즉시 통지
