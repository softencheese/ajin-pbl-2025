# 아진산업 PBL RFID 공정·물류 시스템 헌법

> **목적**: RFID 기반 팔레트 추적 시스템의 spec 생성을 위한 핵심 원칙 정의  

---

## 핵심 원칙 (Core Principles)

### I. 현장 중심 설계 (NON-NEGOTIABLE)
- 요구사항은 "현장 시나리오"와 "작업 동선" 기준으로 정의
- 화면/기능은 특정 공정 단계와 작업 행위에 명확히 대응

### II. 팔레트 중심 아키텍처
- **관리 단위**: 팔레트(Pallet)가 모든 추적의 기본 단위
- **RFID 매핑**: 팔레트와 RFID 태그는 1:1 매핑
- **빠른 회수**: 기본적인 팔레트는 **이전 공정 OUT → 진행 공정 IN 까지만 사용** 후 즉시 회수 (완제품 제외)

### III. 양방향 추적성 (NON-NEGOTIABLE)
- **정방향**: 원자재(코일 번호) → 중간품 LOT → 팔레트 → 완제품
- **역방향**: 완제품 → 조립품 구성 요소 → 중간품 LOT → 원자재(코일 번호)
- **불변 규칙**: 추적 키(코일 번호, LOT 번호, 팔레트 번호, RFID EPC) 절대 삭제/재사용 금지
- **이벤트 로그**: 모든 상태 변경은 `pallet_histories`에 영구 기록

### IV. 상태 기계 엄격 관리
**9가지 팔레트 상태**:
```
중간품: Generated → Empty → Stock → Consuming → Deregistered
완제품: Generated → Empty → Finished → Deregistered
예외: Hold (검증 실패), Defect (불량)
```

**실제 공정 흐름**:
- **원자재 입고**: LOT만 DB 등록 (팔레트 추적 시작 전)
- **샤링 OUT (첫 공정)**: 제품을 팔레트에 적재하면서 추적 시작
  1. 팔레트 생성 (Generated)
  2. RFID 태그 매칭 (Empty)
  3. OUT 리더기 태깅 (Stock) - 적재는 공정 외부에서 발생
- **중간품 공정 (프레스 등)**:
  - IN: Stock → Consuming → Deregistered (소비)
  - OUT: Empty → Producing (적재) → Stock (완료)
- **완제품 조립**:
  - IN: Stock → Consuming → Deregistered (소비)
  - OUT: Empty → Producing → Finished (완료)

**핵심 제약**:
- Finished 상태는 **완제품(`parts.is_final_product = TRUE`)만 허용**
- **샤링만 예외**: Empty → Stock 직접 전환 (적재가 공정 외부)
- 나머지 중간품 공정: Empty → Producing → Stock (일반 흐름)
- 완제품은 Stock 거치지 않고 Empty → Finished로 직접 전환
- Hold 상태는 명시적 해제 전까지 다른 생산 상태로 전환 불가
- Deregistered/Defect는 종료 상태 (재사용 시 새로 Generated)

### V. 검증 로직 차별화
| 검증 | 실패 시 동작 | Override | 부저 | 투입 가능 여부 |
|------|------------|---------|------|---------------|
| **오투입** (품번 불일치) | 투입 즉시 **차단** (BLOCK) | ❌ 불가 | 3회 | ❌ 투입 불가 |
| **FIFO 위반** | **경고** (WARNING) 표시 | ✅ 가능 (무시하고 투입) | 3회 | ✅ 투입 가능 (특별한 경우) |

**검증 시점**: RFID 태그 스캔 시 실시간 (500ms 이내)

**FIFO 위반 처리**:
- 부저 3회 울려 경고 (오류 수준)
- 화면에 경고 메시지 표시 (더 오래된 재고 존재)
- 작업자 판단으로 무시하고 투입 가능 (긴급 생산, 특별 지시 등)
- 무시하고 투입 시 이력에 "FIFO 위반 무시" 기록 (사유는 선택)

### VI. 단순·직관적 UX
- 최소 클릭/스캔으로 업무 완료
- 교육 없이도 이해 가능한 인터페이스
- 에러 메시지에 명확한 사유와 다음 행동 지침 포함
- 공정별 필요 정보만 노출

### VII. 데이터 무결성
**필수 제약**:
- 팔레트는 하나의 LOT만 연결 (`lot_id` 단일 FK)
- 모든 LOT는 `items.id`와 연결 필수
- LOT 간 추적은 `lot_genealogy` 테이블로 관리
- RFID EPC 코드는 시스템 전체에서 유일 (UNIQUE 제약)

**불변 로그**:
- `pallet_histories` 테이블은 절대 삭제 금지
- 모든 상태 변경은 타임스탬프, 행위자, 컨텍스트와 함께 기록

### VIII. 하드웨어 장애 허용
- RFID 리더기 연결 끊김, 네트워크 중단 시 우아한 처리
- 중요 작업은 재시도 가능
- 모든 하드웨어 이벤트 기록
- 리더기는 시각적 + 청각적 피드백 필수

### IX. 테스트 우선
- 핵심 로직은 코드 테스트 + 공정 시나리오 시뮬레이션 후 배포
- 테스트 데이터는 실제 공정 흐름 반영 (원자재 입고 → 샤링 → 프레스 → 조립 → 출하)
- 배포 전 필수: 전 공정 시뮬레이션 1회 + 양방향 추적 각 1회 검증

### X. 점진적 확장
- 초기: 필수 흐름 (정상 공정, 기본 FIFO, 기본 재고/이력 조회)
- 이후: 예외 케이스와 확장 기능 단계적 추가
- 기능 추가 시 기존 데이터 구조 최대한 유지
- 변경 시 마이그레이션 계획 + 롤백 방안 필수

## 데이터 아키텍처 핵심

### 핵심 개념: 품목(Item)과 LOT의 분리
- **품목(Item)**: "무엇인가?" - 제품의 종류/규격 정의 (원자재코드, 품번)
- **LOT**: "어떤 것인가?" - 실물 인스턴스 추적 (시스템 생성 고유 번호)
- **원자재 코드는 품번과 동일한 개념** (동일 코드로 여러 번 입고 가능)
- **LOT 번호는 시스템 자동 생성** (입고/생산 시마다 새로 발행)

### 8개 핵심 테이블
**마스터 (3개)**:
- `items`: 통합 품목 마스터 (RAW:원자재, WIP:재공품, PRODUCT:완제품)
- `processes`: 공정 정보 (입고, 샤링, 프레스, 조립, 출하)
- `rfid_reader_locations`: 리더기-공정-위치 매핑 (IN/OUT/HOLD/DEFECT/FINISH/RETURN)

**LOT 관리 (2개)**:
- `lots`: 통합 LOT 관리 (원자재~완제품 모두 포함, `lot_number`는 시스템 생성 고유값)
- `lot_genealogy`: LOT 족보 (투입-산출 관계, 추적성 핵심)

**RFID (3개)**:
- `pallets`: 팔레트 상태 관리 (9가지 상태, 단일 `lot_id` 연결)
- `pallet_histories`: 불변 이력 로그
- `rfid_tags`: RFID 태그 관리

### 5개 추적성 뷰
- `v_pallet_status`: 팔레트 현황
- `v_stock_inventory`: 재고 현황 (FIFO용)
- `v_lot_forward_trace`: 정방향 추적 (원자재 → 완제품)
- `v_lot_backward_trace`: 역방향 추적 (완제품 → 원자재)
- `v_lot_full_genealogy`: LOT 전체 족보 조회

## 개발 워크플로우

### 5단계 프로세스
1. **현장 시나리오 정의**: 공정/작업자/동선/상태 변화 문서화
2. **흐름도 설계**: 팔레트 상태 전이 + 예외 처리 + 양방향 추적 경로
3. **테스트 케이스**: 정상 시나리오 + 최소 1개 예외 (FIFO 위반, 오투입 등)
4. **구현 및 자기 점검**: RESTful API, 500ms 응답, 이벤트 로깅
5. **현장 데모**: 실제 공정 용어 확인, 사용성 검증

### PR 필수 체크
- [ ] 상태 전이가 헌법 규칙 준수
- [ ] 양방향 추적성 유지 (끊김 없음)
- [ ] 실제 공정 용어 사용
- [ ] 태그 스캔 → 피드백 500ms 이내

### 배포 전 필수
- [ ] 전 공정 시뮬레이션 1회 이상
- [ ] 정방향 추적 검증 (코일 → 제품)
- [ ] 역방향 추적 검증 (제품 → 코일)
- [ ] 롤백 방안 + 현장 매뉴얼
